# Design Spec: `/ui-into-preview`

**Date**: 2026-06-21
**Status**: Approved — Ready for Implementation
**Skill repo**: `ui-gernreate-from-plan`
**Subskill path**: `subskills/ui-preview/SKILL.md`
**Command**: `/ui-into-preview`

---

## 1. Purpose

`/ui-into-preview` is the fourth command in the UI Bridge workflow. It takes the HTML
prototypes generated by `/ui-implement` and produces a fully self-contained, GitHub
Pages-deployable canvas presentation tool — no server, no backend, no build step.

The output is a folder (`ui-preview/`) that a designer can push directly to GitHub Pages
and share a URL with any client. Clients see every page of the UI as floating frames on
an infinite canvas, wired together with flow arrows, navigable with a presentation mode,
and fully interactive via a preview toggle — with zero installation required.

## 3. Output Structure

```
ui-preview/
├── index.html          ← Canvas app — static, regenerated only when page list changes
├── manifest.json       ← Page/doc registry — structure source of truth
├── canvas-state.json   ← Layout state — positions, wires, story stops
├── pages/              ← Copied from [PROTOTYPE_DIR]/
│   ├── index.html
│   ├── courses.html
│   └── ...
└── docs/               ← Copied from spec folder
    ├── spec.md
    ├── plan.md
    └── ...
```

**Separation of concerns:**

| File | What it owns | Regenerated when |
|---|---|---|
| `index.html` | Canvas app code (HTML/JS/CSS) | Pages added or removed |
| `manifest.json` | Page list, groups, IDs, metadata | Pages added, removed, or renamed |
| `canvas-state.json` | Positions, flow wires, story stops | Never re-generated from scratch after creation. Existing layout is preserved and only new pages may be appended. |
| `pages/*.html` | Prototype content | On every command run (copy) |
| `docs/*.md` | Spec content | On every command run (copy) |

**Critical rule**: The Python script **never overwrites** `canvas-state.json` if it already
exists. A designer's saved layout is never destroyed by re-running the command.

## 4. `manifest.json` Schema

Generated by the Python script. Never edited by hand.

```json
{
  "version": 1,
  "generated": "2026-06-21",
  "project": "[PROJECT_NAME]",
  "pages": [
    {
      "id": "page_home",
      "slug": "index",
      "title": "Home",
      "group": "Public",
      "file": "pages/index.html",
      "direction": "rtl"
    },
    {
      "id": "page_courses",
      "slug": "courses",
      "title": "Courses",
      "group": "Public",
      "file": "pages/courses.html",
      "direction": "rtl"
    },
    {
      "id": "page_admin_login",
      "slug": "admin-login",
      "title": "Admin Login",
      "group": "Admin",
      "file": "pages/admin-login.html",
      "direction": "ltr"
    }
  ],
  "docs": [
    {
      "id": "doc_spec",
      "title": "Specification",
      "file": "docs/spec.md"
    },
    {
      "id": "doc_plan",
      "title": "Implementation Plan",
      "file": "docs/plan.md"
    }
  ],
  "nav_wires": [
    { "from": "page_home",    "to": "page_courses" },
    { "from": "page_courses", "to": "page_course_detail" }
  ]
}
```

**`nav_wires` lives in `manifest.json`, not `canvas-state.json`.** The Python script
scans every page's HTML for `<a href>` links that resolve to other pages in the manifest
on each run, and writes the result into `manifest.json`. This guarantees nav wires are
always in sync with the actual HTML — they cannot go stale. The canvas reads nav wires
from `manifest.json` at load time and renders them as thin grey curves; they are never
stored in `canvas-state.json`.

**ID format**: `page_<slug_with_underscores>` for pages, `doc_<name>` for docs.
IDs are **permanent** — they survive slug/title renames and are the foreign key for all
wires, layer references, and story stops in `canvas-state.json`.

**Group field**: Any string is valid — `"Public"`, `"Admin"`, `"Student"`,
`"Instructor"`, `"Partner Portal"`, etc. The layout engine reads group values from
`page-map.json` (which itself reads from the spec). No groups are hardcoded in the skill.

## 5. `canvas-state.json` Schema

The single source of truth for the designer's layout. Loaded at runtime via
`fetch('./canvas-state.json')`. Never baked into `index.html`.

**`canvas-state.json` stores only what the designer controls**: frame positions, manually
drawn flow wires, doc card positions, and story stops. Auto-detected nav wires are
excluded — they live in `manifest.json` and are regenerated on every Python run.

```json
{
  "version": 1,
  "frames": [
    {
      "id": "page_home",
      "x": 120,
      "y": 80,
      "width": 380,
      "height": 620,
      "visible": true
    }
  ],
  "wires": [
    {
      "id": "wire_001",
      "from": "page_courses",
      "to": "page_course_detail",
      "label": "View Course",
      "type": "flow",
      "color": "#2563EB"
    }
  ],
  "docs": [
    {
      "id": "doc_spec",
      "x": 1800,
      "y": 120,
      "width": 480,
      "visible": true
    }
  ],
  "story_stops": [
    {
      "id": "stop_001",
      "label": "Public Site Overview",
      "viewport": { "x": 0, "y": 0, "zoom": 0.45 }
    },
    {
      "id": "stop_002",
      "label": "Registration Flow",
      "viewport": { "x": -380, "y": 200, "zoom": 0.9 }
    }
  ]
}
```

**Wire types:**
- `"nav"` — sourced from `manifest.json` (regenerated by the Python script on every run
  by scanning `<a href>` in each page HTML). Thin grey. Toggled off by default. Never
  stored in `canvas-state.json` — always fresh from the latest HTML.
- `"flow"` — manually drawn by designer. Bold, colored, labeled. Always visible (unless
  hidden in Layers panel). Stored in `canvas-state.json`.

**Version migration**: When `index.html` loads a state file, it checks `state.version`.
If the version is older than the current app version, it runs migration functions before
applying state. No old state file ever breaks the canvas.

## 6. Canvas App — `index.html`

Fully self-contained — all CSS and JS inline. No `<link>`, no `<script src>`,
no external CDN references. Loads `manifest.json` and `canvas-state.json` via `fetch()`
on startup (same-origin on GitHub Pages).

### 6.1 Page Structure

```
┌────────────────────────────────────────────────────────────────┐
│  [Select] [Pan] [Wire] [Add Doc]  ─────────  [Present] [Save] │ ← Toolbar
├─────────────────┬──────────────────────────────────────────────┤
│  Layers Panel   │                                              │
│                 │         I N F I N I T E   C A N V A S       │
│  ▼ Pages (10)   │                                              │
│    👁 Home      │  ┌──────────────────┐   ┌──────────────────┐│
│    👁 Courses   │  │ Home        [×]  │   │ Admin Login [×]  ││
│    ...          │  │┌──────────────┐  │   │┌──────────────┐  ││
│                 │  ││   iframe     │  │ → ││   iframe     │  ││
│  ▼ Wires (2)   │  ││              │  │   ││              │  ││
│    👁 Reg Flow  │  ││ [BLOCKER]    │  │   ││ [BLOCKER]    │  ││
│                 │  │└──────────────┘  │   │└──────────────┘  ││
│  ▼ Docs (2)    │  │ [Preview Mode]   │   │ [Preview Mode]   ││
│    👁 spec.md   │  └──────────────────┘   └──────────────────┘│
│    👁 plan.md   │                                         [⊞] │ ← Minimap
└─────────────────┴──────────────────────────────────────────────┘
```

### 6.2 Infinite Canvas

- **Pan**: drag the canvas background
- **Zoom**: mouse wheel / trackpad pinch / `+` `-` keys / `Ctrl+0` to reset to fit-all
- Implementation: single `<div class="canvas-viewport">` with CSS
  `transform: translate(Xpx, Ypx) scale(Z)` updated on every interaction
- Zoom range: 10% – 300%
- All frame positions are stored in canvas coordinates (not screen coordinates)

### 6.3 Frame Cards

Each page in `manifest.json` renders as a frame card:

```html
<div class="frame-card" data-id="page_home" style="transform: translate(120px, 80px)">
  <div class="frame-title-bar">
    <span class="frame-title">Home</span>
    <span class="frame-group-badge">Public</span>
    <button class="frame-close">×</button>
  </div>
  <div class="frame-body">
    <iframe src="./pages/index.html" loading="lazy"></iframe>
    <div class="interaction-blocker"></div>
  </div>
  <button class="preview-toggle">Preview Mode</button>
</div>
```

**Interaction blocker**: `position: absolute; inset: 0; z-index: 10` on top of the iframe.
No JS is injected into the iframe. No cross-frame access required. Works with any iframe
CSP. All links and inputs in the page are unreachable.

**Preview Mode toggle**: clicking "Preview Mode" on a frame sets `.preview-mode` on that
frame card, which hides the blocker via CSS (`display: none`). The iframe becomes fully
interactive for testing. Clicking again re-enables the blocker.

**Double-click to focus**: double-clicking a frame animates the canvas viewport to fill
that frame edge-to-edge. `Esc` or clicking outside the frame returns to the previous zoom.

**Drag to reposition**: dragging the title bar moves the frame. Position updates are held
in memory and persisted to `canvas-state.json` on Save.

### 6.4 Layers Panel

Left sidebar, always visible. Sections match the three top-level keys in `canvas-state.json`:

```
▼ Pages (10)          ← collapsible, count shows visible/total
   👁  Home
   👁  Courses
   ⊘  Course Detail   ← eye closed = hidden on canvas
   ...
▼ Flow Wires (3)
   👁  Registration Flow
   👁  Admin Login Flow
▼ Docs (2)
   👁  spec.md
   👁  plan.md
```

- Click any item → canvas animates to it and highlights it with a brief ring
- Eye icon toggles `visible` in the frame/doc state
- Group header eye icon toggles the entire group
- Panel is hidden in Presentation Mode

### 6.5 Minimap

Bottom-right corner. Thumbnail view of the entire canvas:
- All frames drawn as labelled rectangles at reduced scale
- Current viewport shown as a highlight rectangle
- Click anywhere on minimap → canvas jumps to that region
- Hidden in Presentation Mode

### 6.6 Toolbar

```
[Select] [Pan] [Wire] [Add Doc]  ──  [Nav Wires ○] [Zoom: 75%] [+] [-]  ──  [Present] [Save]
```

| Control | Action |
|---|---|
| Select | Default mode — click to select/drag frames |
| Pan | Click-drag moves the canvas (alt: middle mouse / space+drag in Select mode) |
| Wire | Click source frame → click target frame → type label → creates flow wire |
| Add Doc | Dropdown of available docs from `manifest.json` |
| Nav Wires toggle | Shows/hides auto-detected nav wires |
| Zoom % | Click to type exact zoom value |
| Present | Enters Presentation Mode |
| Save | Downloads `canvas-state.json` with current state |

### 6.7 Wiring System

**SVG overlay**: a single `<svg>` element covers the entire canvas viewport, drawn above
all frames. Wires are SVG cubic bezier paths with arrowhead markers.

**Auto nav wires** (type: `"nav"`):
- Generated by the Python script by scanning each page's HTML for `<a href="...">` links
  that point to other pages in the manifest
- Stored in `canvas-state.json` under `wires` with `type: "nav"`
- Drawn as thin grey dashed curves (`stroke: #94A3B8; stroke-width: 1.5; stroke-dasharray: 4`)
- Toggled via "Nav Wires" toolbar button; off by default
- Hidden in Presentation Mode

**Manual flow wires** (type: `"flow"`):
- Created in Wire mode: click source frame → click target frame → label prompt appears
- Drawn as bold solid curves with arrowhead (`stroke-width: 2.5`)
- Color assigned from a rotating palette of 6 accessible colors
- Label rendered at the wire midpoint in a small pill
- Wires re-route dynamically as frames are dragged (both endpoints anchor to frame center)
- Visible in Presentation Mode

### 6.8 Markdown Cards

Doc items from `manifest.json` are placed as cards on the canvas:

- Clicking "Add Doc" in toolbar or double-clicking a doc in the Layers panel places it
- Markdown rendered to HTML inline using a ~80-line vanilla JS parser
  (handles: `#` headers, `**bold**`, `*italic*`, `` `code` ``, code blocks, `-` lists, links).
  The parser is intentionally limited and supports only this documented subset — it does
  not support full CommonMark features such as tables, task lists, raw HTML, or nested blocks.
- Cards are draggable (same drag mechanic as frames)
- Cards have a title bar, a scrollable content area, and a resize handle
- No iframe — content is rendered directly in the canvas DOM

### 6.9 Presentation Mode

Entered via "Present" button or `F5`. Exits via `Esc`.

**On enter:**
- Canvas goes fullscreen (`document.documentElement.requestFullscreen()`)
- Toolbar hidden
- Layers panel hidden
- Minimap hidden
- Auto nav wires hidden
- Only flow wires visible
- Story stop navigation bar appears at the bottom:
  ```
  ← [2 / 4]  Registration Flow  →
  ```

**Story stop navigation:**
- `←` `→` arrow keys or clicking nav arrows moves between story stops
- Transition: smooth CSS `transform` animation (300ms ease-in-out) on the canvas viewport
- Each stop restores the saved `viewport: { x, y, zoom }`

**Adding story stops** (in normal mode):
- "Add Stop" button in toolbar (always visible in normal mode)
- Saves the current viewport as a new story stop with a label prompt
- Stops can be reordered by drag in the Layers panel (future: story_stops group)
- Stops stored in `canvas-state.json`

> **Future note**: v2 may optionally bind story stops to frame IDs so the viewport
> recalculates automatically after major layout changes. In v1, story stops store
> absolute viewport coordinates only (`x`, `y`, `zoom`).

## 7. Auto Layout Engine

Triggered only when `canvas-state.json` does not yet exist (first run).

**Algorithm:**
1. Read all unique `group` values from `manifest.json` pages, in order of first appearance
2. For each group, collect its pages in `plan.md` flow order
3. Lay pages out in a vertical column within the group (top-to-bottom, 40px gap)
4. Place group columns left-to-right with a 120px gap between groups
5. Frame default size: 380px wide × 620px tall
6. Canvas origin (0, 0) is the top-left of the first group

**Example output for EdTech project:**

```
[Public cluster — x: 0]        [Admin cluster — x: 500]
  Home          (0, 0)           Admin Login     (500, 0)
  Courses       (0, 660)         Admin Dashboard (500, 660)
  Course Detail (0, 1320)        Registrations   (500, 1320)
  Experts       (0, 1980)        ...
  ...
```

**Flexibility**: No group names are hardcoded. Any `group` value in `page-map.json`
produces a cluster. A project with groups `["Student", "Instructor", "Admin"]` produces
three clusters automatically.

## 8. State Persistence

### On Load

```js
Promise.all([
  fetch('./manifest.json').then(r => r.json()),
  fetch('./canvas-state.json').then(r => r.json()).catch(() => null)
]).then(([manifest, state]) => {
  initCanvas(manifest, state ?? generateDefaultLayout(manifest))
})
```

If `canvas-state.json` is missing or fails (e.g., first GitHub Pages deploy without the
file committed), the canvas generates a default layout from the manifest and works normally.

### Version Migration

```js
function migrateState(state) {
  if (!state.version || state.version < 1) {
    // handle pre-versioned state files
    state.version = 1
    state.story_stops = state.story_stops ?? []
  }
  // future: if (state.version === 1) migrateV1ToV2(state)
  return state
}
```

### On Save

"Save" button triggers a download of the current in-memory state as `canvas-state.json`.

```js
const blob = new Blob([JSON.stringify(state, null, 2)], { type: 'application/json' })
const a = document.createElement('a')
a.href = URL.createObjectURL(blob)
a.download = 'canvas-state.json'
a.click()
```

The designer saves the downloaded file to the repo root (or `ui-preview/`), commits,
and pushes. The live GitHub Pages URL reflects the new layout on next load.

### Drag-Drop Import

Dragging any `.json` file onto the canvas:

```js
document.addEventListener('dragover', e => e.preventDefault())
document.addEventListener('drop', e => {
  const file = e.dataTransfer.files[0]
  if (!file?.name.endsWith('.json')) return
  file.text().then(text => {
    const state = migrateState(JSON.parse(text))
    applyState(state)
  })
})
```

State is applied immediately. A "Save" click after import downloads the migrated state.

## 9. Python Script — `scripts/ui_preview_workflow.py`

```
python scripts/ui_preview_workflow.py \
  --prototype-dir ui-prototypes \
  --spec-dir specs/001-edtech-marketing-crm \
  --output-dir ui-preview \
  --page-map .ui-bridge/page-map.json
```

**Steps:**

1. Read `[page-map]` → extract page list with slugs, titles, groups, directions
2. Read `[prototype-dir]/*.html` → verify all pages in page-map exist as files
3. Read `[spec-dir]/*.md` → collect doc files
4. Copy `[prototype-dir]/*.html` → `[output-dir]/pages/`
5. Copy `[spec-dir]/*.md` → `[output-dir]/docs/`
6. Scan each copied HTML for `<a href>` links resolving to other pages → build `nav_wires` list
7. Generate `[output-dir]/manifest.json` (always regenerated — includes fresh `nav_wires`)
8. If `[output-dir]/canvas-state.json` does NOT exist:
   - Generate default layout (auto layout algorithm, Section 7)
   - Write `canvas-state.json`
9. If `[output-dir]/canvas-state.json` EXISTS:
   - Read it, check for new pages not yet in `frames[]`
   - Append any new pages to `frames[]` using auto-layout position for the new item only
   - Write updated `canvas-state.json`
   - **Never reposition existing frames**
10. Generate `[output-dir]/index.html` (canvas app — always regenerated)
11. Print: `ui-preview/ ready. Push to GitHub and enable Pages.`

**On re-run when pages are added**: new pages appear on the canvas at a safe default
position. Existing frames keep their designer-placed positions.

## 10. GitHub Pages Deployment

```
repo/
└── ui-preview/    ← set as GitHub Pages source
    ├── index.html
    ├── manifest.json
    ├── canvas-state.json
    ├── pages/
    └── docs/
```

**Setup steps** (included in canvas app as a dismissable info banner on first load):
1. Push the `ui-preview/` folder to GitHub
2. Go to repo Settings → Pages → Source: `main` branch, `/ui-preview` folder
3. Wait ~60 seconds → share `https://[user].github.io/[repo]/`

**Same-origin guarantee**: since all files (`pages/*.html`, `manifest.json`,
`canvas-state.json`) are served from the same GitHub Pages domain, `fetch()` and
iframe access both work without CORS issues.

## 12. What This Skill Does NOT Do

- Does not modify any file in `ui-prototypes/` — it only copies from it
- Does not modify `plan.md`, `tasks.md`, or any spec file
- Does not require a backend, database, or local server to use
- Does not use React, Vue, or any frontend framework
- Does not embed page HTML into `index.html` as `srcdoc` — pages stay as separate files
- Does not overwrite `canvas-state.json` when it already exists
- Does not implement real-time multi-user collaboration (that is a v2 feature)

## 13. Future Scope (Not in v1)

Explicitly out of scope for this version. Captured here to prevent scope creep:

- Frame colors / tags / annotations
- Comments on frames or wires
- Swimlanes
- Real-time collaborative editing (WebSocket/CRDTs)
- Version history / undo-redo beyond browser session
- Export to PDF or image
- Embed mode (iframe the canvas itself)
- Per-frame zoom lock
- Component-level wiring (wire to a specific section of a page)
